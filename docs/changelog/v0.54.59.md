# v0.54.59

**Summary:** Activate fail-closed proxy protocol and outcome recovery

- Make replacement servers emit the strict `brainCommandInterface` initialise
  header and reject every tool call before lookup when the running proxy marker
  is missing, malformed or outside protocol 2.
- Return ordinary `proxy_restart_required` MCP results with `effects: none` so
  an old live proxy can explain the required restart without resolving retired
  names, translating requests or executing effects.
- Make proxy 0.6.0 pass its running-process protocol marker, validate the child
  header and bind every staged granular call to an exact accepted-call
  record with proxy-owned invocation identity before child dispatch.
- Replay planned version-drift calls only after positive command-level
  compatibility proof; incompatible replacements return `interface_changed`
  and force tool re-discovery without child dispatch.
- Separate unexpected loss from planned drift: retry a compatible read orphan
  once, never replay a mutation, and query `invocation.read` after restart.
  Conclusive privacy-minimal receipts are reported; absence, corruption or an
  explicitly unknown receipt becomes non-retryable `command_outcome_unknown`
  with the queryable invocation reference.
- Keep `install_proxy_protocol_gate()` until the minimum supported live proxy
  always supplies compatible protocol metadata; only its cutover-specific
  wording may then be retired. The gate never becomes semantic translation.
- Align Brain Core, the README badge and `BRAIN_INSTALL_REF` at v0.54.59.
  `BRAIN_CLI_VERSION` remains 1.2.0 because the public CLI grammar is still
  staged for the coordinated breaking cutover.
