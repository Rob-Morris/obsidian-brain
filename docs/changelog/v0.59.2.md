# v0.59.2

**Summary:** Make mutation admission and staged contracts content-exact

**Type:** Brain Core patch; correctness, privacy and repository integrity

## Fixed

- Require content-sensitive router-source verification before every mutation admission. The bounded stat signature remains available for non-authoritative status reporting, but a same-size source edit with a restored timestamp can no longer be treated as fresh.
- Materialise the Git index and run its own repository-contract checker and parser imports during staged validation. The hook fails closed when its bootstrap closure has unstaged changes, preventing partially staged validator semantics from approving a different executable snapshot.
- Classify post-edit `ValueError` failures while the vault mutation lock is still held. If the revision changed or cannot be probed, the command returns `command_outcome_unknown` instead of advertising a safe retry.
- Keep unexpected direct-script failures privacy-bounded on public stderr while sending full exception detail, command identity and correlation metadata to the trusted diagnostic sink once invocation context exists.
- Reject Windows-reserved names, forbidden and control characters, and trailing dots or spaces from portable manifest paths on every host platform. Attachment naming and manifest validation now share the same filename-segment rule.

## Verification

- Router regressions change a living source without changing its size or timestamp and assert that mutation admission rejects the stale compiled router.
- Staged-checker regressions diverge staged and working parser behavior in both directions and assert that only the staged semantics decide the result.
- Mutation tests assert that the post-failure revision probe remains inside the vault lock; direct-script tests assert bounded public output and correlated trusted diagnostics.
- Table-driven path tests cover Windows device names, forbidden characters, trailing dots and spaces, and control characters.
