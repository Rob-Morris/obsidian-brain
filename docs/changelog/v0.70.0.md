# v0.70.0

**Summary:** BREAKING — Require explicit MCP clients and migrate registration

**Type:** Breaking setup contract; canonical MCP ownership migration

## Changed

- User registration uses the installed CLI's isolated stdio bootstrap and a machine-owned ledger, independent of a selected Brain. Its absolute base Python is installation-owned, not a rotating dependency environment.
- Setup/configure requires an explicit client, including `all`. User/project/local projections share strict, ownership-preserving planning. Repair restores deleted owned projections without installing unselected clients.
- Workspace, Brain and machine repair compose registered targets and deduplicate shared runtime environments. Upgrade includes user-only and external-project registrations. Uninstall stops on incomplete cleanup; persisted references protect stopped runtimes from pruning.
- Legacy ownership migrates through durable before/after evidence, resumable conflict checks and a persisted-command normal MCP read. Normal repair no longer adopts legacy or unowned client files.
- CI fixtures use the current MCP tool/access contract and portable stdio reads; semantic-repair checks no longer depend on optional packages installed on the host, and log contention tests coordinate the actual competing operations.

## Migration

Install the coordinated CLI 4/Core 0.70 distribution. Inspect `brain mcp migrate --dry-run --json`, then run `brain mcp migrate --json` and the needed repair breadth. Modified entries, missing registered targets and conflicting ownership require explicit resolution. Keep migration evidence until verification succeeds; do not run older Core user-registration writers after cutover.

For unattended fresh setup, add `--client all` (or an individual client); scaffold-only `--skip-mcp` remains available. A relocated base Python is recovered by reinstalling the CLI with `--bootstrap-python /absolute/python3.12`. Client-host reconnect/trust remains separate from successful Brain-side repair.
