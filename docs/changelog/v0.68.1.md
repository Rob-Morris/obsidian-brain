# v0.68.1

**Summary:** Fix consent discovery and restore configuration on upgrade rollback

**Type:** patch

## Changed

- Rename the unusable access.status command filter to target_command_id, matching command.describe, and update access.status to command version 3 while keeping routing identity fields sealed.
- Update access.status next_action arguments and public examples, and reject catalogue request fields that collide with command_id, command_version or brain_operation before they can advertise an unusable interface.
- Extend resolver and real MCP regressions so advertised command-filter and blanket-consent discovery routes resolve through the production adapter.
- Restore and verify upgrade snapshots in reverse phase order so a failed authorisation migration returns configuration and migration markers to their original state. Preserve rollback diagnostics and backup retention when restoration cannot be verified.
