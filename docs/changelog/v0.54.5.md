# v0.54.5

**Migrate portable router, environment, and link-check command owners**

- Add separate typed request/result/executor/resolver/catalogue owners for
  `runtime.read-environment`, `vault.read-router`, and `links.check` under
  domain-specific `_application` packages.
- Extract environment and router metadata views into adapter-free
  `_portable/router_views.py`; the legacy `read.py` environment/router
  handlers delegate to the same lower semantics without changing their public
  output.
- Return runtime state as sorted typed scalar facts and router state as an
  exact command-specific payload covering rules, versions, compilation/source
  hashes and artefact-index source facts. No unbounded result metadata bag is
  introduced.
- Reuse the existing portable wikilink checker directly for `links.check`, so
  link diagnosis works without compiled-router availability and returns typed
  warning/info findings with no effects.
- Register all three owners in the same selected-Brain catalogue and strict
  resolver as the earlier commands; zero-input requests reject every extra
  field and are immediately visible through `command.list`.
- Add installed command-vault evidence for scalar environment facts, exact
  router metadata, link-finding summaries, resolver identity and preserved
  legacy read behaviour.
- Keep public MCP, CLI and direct-script grammar unchanged; the migration is
  internal until the coordinated cutover.
- Align `src/brain-core/VERSION`, the README badge, and `BRAIN_INSTALL_REF`
  with v0.54.5. `BRAIN_CLI_VERSION` and `PROXY_VERSION` remain unchanged
  because their public behaviour and protocols did not change.
