# v0.68.0

**Summary:** BREAKING — Replace access.request leases with instance-owned consent

**Type:** minor

## Changed

- Separate enduring credential permissions from initial authorisation and explicit operation or command consent in `access.prepare`, `access.request` and `access.reduce`, without timers, renewal or silent request-and-retry.
- Expose bounded `access.status` and `vault.read-config` inspection, static above-permission `command.describe` discovery, and a `session.start` access summary within a 16,000-byte bootstrap envelope.
- Bind `brain_operation` selectors and `brain session run` jobs to private consent owners; require atomic `OwnedReceiptStore` admission claims and expose independent execution and effect outcomes through `invocation.read` without replaying lost calls.
- Migrate proven stored `initial_profile` settings conservatively through `migrate_to_0_68_0.py`, preserve unresolved external approval as `vault.access.request_policy=migration_required`, and provide audited CLI-only `permission.set-profile` for existing operators.

## Migration

- Upgrade Brain Core to `0.68.0` with CLI `3.3.0` and restart MCP clients to load proxy `0.10.0`; the command catalogue moves to interface epoch `3` and the private proxy protocol to `4`.
- Replace lease-based `access.request` callers with reviewed operation or command consent. Configure harness approval on the distinct `access_request` tool; use `brain session run -- program` for exceptional CLI work spanning invocations.
- Inspect `vault.read-config` after migration. Resolve any `migration_required` policy or conflicting legacy access settings explicitly before requesting exceptional consent; historical `.brain/local/access-state.json` records confer no new grants.
