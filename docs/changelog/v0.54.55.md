# v0.54.55

**Summary:** Enforce structural result parity across local command adapters

- Project known semantic request failures through `brain.command-result/1`
  instead of falling back to direct-script-only stderr.
- Preserve unstructured exit-2 failures only for transport grammar that cannot
  identify an installed command.
- Add a deterministic parity harness spanning typed Python, the dynamic
  adapter, direct script, real FastMCP and composed local CLI execution.
- Require equivalent valid and invalid intent to produce the same canonical
  result envelope, error details, effects and exit category.
- Make one local CLI presentation function own JSON versus human stdout/stderr
  placement for both application and launcher results.
- Reject selected-Brain child stderr, malformed structure, identity drift and
  any mismatch between structural result and canonical exit category.
