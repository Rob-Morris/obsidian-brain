# v0.54.4

**Migrate portable artefact read, list, and outline command owners**

- Add one typed request, result, executor, resolver and catalogue entry for each
  of `artefact.read`, `artefact.list`, and `artefact.outline` under the
  domain-organised `_application/artefact/` package.
- Extract artefact read, list filtering/pagination and structural-outline
  semantics into adapter-free `_portable` modules. Existing `read.py`,
  `list_artefacts.py`, and `outline.py` delegate to those lower owners and keep
  their characterised public behaviour during migration.
- Return structural errors with `effects: none`: missing artefacts are
  `not_found`, path escapes and malformed list filters are `invalid_request`,
  and missing derived read state is an explicit `conflict` rather than an
  adapter traceback.
- Give new list items an explicit canonical `reference` and separately named
  `frontmatter_key`, avoiding the legacy output's ambiguous `key` field while
  retaining typed stable pagination and complete list metadata.
- Assemble the migrated commands with the foundational discovery owners in one
  authoritative runtime registry; `command.list` includes each new owner
  immediately and transport resolution yields the same typed requests used by
  direct Python.
- Add installed command-vault owner tests for canonical reads, pagination,
  filters, structural duplicate targets, invalid intent, catalogue identity,
  resolver parity and legacy-adapter preservation.
- Keep MCP, CLI and direct-script names unchanged until the coordinated public
  cutover; this release moves semantic ownership only.
- Align `src/brain-core/VERSION`, the README badge, and `BRAIN_INSTALL_REF`
  with v0.54.4. `BRAIN_CLI_VERSION` and `PROXY_VERSION` remain unchanged
  because their public behaviour and protocols did not change.
