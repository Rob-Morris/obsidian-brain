# v0.54.2

**Establish receipt, version, capability, and launcher contracts**

- Add a bounded, concurrency-safe outcome-receipt store with immutable records,
  retention and count limits, privacy-minimal fields, explicit cleanup, and
  `still_unknown` lookup semantics when no conclusive receipt remains.
- Add strict dynamic request resolution that binds local callers to installed
  command versions, rejects caller-supplied identity fields, and refuses
  unsupported serialised versions before execution.
- Encode independent command, result, catalogue, launcher, interface-epoch and
  proxy-protocol transition rules. Fingerprints remain cache validators and do
  not become replay compatibility evidence.
- Add bounded capability refresh that deduplicates providers, probes them
  concurrently within provider-specific and two-second aggregate deadlines,
  and represents missing, failed or timed-out probes as unknown availability.
- Record every application projection as explicitly supported or unsupported
  with a reason, and include locality and recoverability in canonical
  `capability_unavailable` details.
- Add the separate stdlib-only `brain.launcher-catalogue/1` authority with all
  23 launcher operations from the closed disposition inventory, one owner per
  command, explicit non-application projections and a deterministic
  fingerprint.
- Keep all new surfaces internal. Existing MCP, CLI and direct-script grammar
  remains unchanged until the coordinated breaking cutover.
- Align `src/brain-core/VERSION`, the README badge, and `BRAIN_INSTALL_REF`
  with v0.54.2. `BRAIN_CLI_VERSION` and `PROXY_VERSION` remain unchanged
  because their public behaviour and protocols did not change.
