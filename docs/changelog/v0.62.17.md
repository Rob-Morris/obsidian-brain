# v0.62.17

**Summary:** Keep owner output off the fresh-interpreter reply and scope doctor memory scans

**Type:** Brain Core patch

## Changed

- Redirect file descriptor 1 to stderr inside the child in `_lifecycle/fresh_interpreter.py::reply_channel`, so pip and native download progress written by owners' subprocesses no longer corrupt the JSON reply; reproduced on Linux where a first `retrieval.enable` provisioned successfully and then reported an internal error.
- Pass lifecycle owners to `run_lifecycle_in_fresh_interpreter` as callables rather than dotted strings, keeping the application-to-lifecycle dependency visible to import tooling; the child still resolves and validates `_lifecycle.*` targets only, and catches `Exception` rather than `BaseException`.
- Move the rebuild owner to `_lifecycle/semantic_rebuild.py::rebuild_semantic`, built with `make_result_envelope` like its siblings, and share one `ENCODER_MODULES` tuple in `_semantic/model.py` between the availability probe and `SEMANTIC_RUNTIME_MODULES`.
- Make the doctor footprint scan opt-in via `collect_machine_summary(measure_memory=True)`, with the summary owned by `_machine/process_footprint.py::summarise_runtime_memory`; migration, pruning and upgrade guidance no longer measure processes, and the human report states partial coverage (`2 of 3 live runtime processes (1 unmeasured)`).
- Tidy the encoder: named pooling and normalisation epsilons, no unused `batch_size` or `config.json` snapshot entry, and `semantic_runtime_supported_platform` loses its dead parameters; new tests cover `reply_channel` via captured descriptors, the memory summary, and both untested doctor memory branches.
