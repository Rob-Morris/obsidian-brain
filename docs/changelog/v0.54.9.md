# v0.54.9

**Migrate exact artefact-type and template owners**

- Add distinct typed `type.read/list` and `template.read/list` owners with
  strict request decoding, bounded result payloads and separate catalogue
  identities.
- Make `type.read` and `template.read` select the exact compiled type `key`;
  singular and frontmatter-type aliases remain available only through the
  unchanged legacy adapters until public cutover.
- Return the complete taxonomy document from `type.read` alongside bounded
  identity, classification and source-path fields rather than exposing the
  compiled router's open nested metadata.
- Normalise `TemplateReadPayload.path` and `TemplateListItem.path` to actual
  `.md` paths so callers can pass them directly to exact `vault.read-file`.
- Move type/template filtering and legacy-compatible reads into
  `_portable/type_definitions.py`, preserving current MCP and direct-script
  output while removing duplicate semantic implementations.
- Cover exact identity, list filtering, typed classification, source content,
  transport rejection and legacy parity in
  `tests/application/test_type_template_owners.py` and existing read/list tests.
- Align `src/brain-core/VERSION`, the README badge, and `BRAIN_INSTALL_REF`
  with v0.54.9. `BRAIN_CLI_VERSION` and `PROXY_VERSION` remain unchanged
  because their dispatch and protocols did not change.
