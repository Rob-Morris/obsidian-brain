# v0.54.45

**Summary:** Add authoritative application command discovery

- Expand `command.list` v2 from bare identifiers to bounded typed summaries
  carrying application ownership, version, projections, tier, locality,
  authority, effects, retry safety, providers, availability and lifecycle.
- Derive availability from one trusted capability snapshot without executor
  probes; explicit refresh deduplicates providers and retains a bounded snapshot
  window so subsequent pages reuse the same observation.
- Expand `command.describe` v2 with strict request/result schemas, result
  branches, stable code vocabularies, provider/safety requirements, projections,
  lifecycle guidance and one minimal catalogue-bound example.
- Make every generated minimal example pass the real request resolver and close
  the previously unobserved missing `skill.search` resolver registration.
- Align `invocation.read` v2 on the canonical scalar `invocation_id` input used
  by recovery actions instead of exposing an adapter-specific nested wrapper.
- Keep selected-Brain discovery application-only; launcher composition remains
  owned by the local CLI projection and public v1 adapters remain unchanged.
