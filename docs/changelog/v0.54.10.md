# v0.54.10

**Migrate strict workspace read and resolution owners**

- Add distinct typed `workspace.read`, `workspace.list` and
  `workspace.resolve` owners with exact slug requests, bounded workspace
  records and separate catalogue identities.
- Make `workspace.read` return hub metadata while `workspace.resolve` returns
  only the resolved data-folder identity; the two intents no longer share an
  ambiguous result shape.
- Add `load_registry_strict()` so canonical commands fail closed on malformed
  `.brain/local/workspaces.json` state rather than presenting corruption as an
  empty registry.
- Add `UnknownWorkspaceError` so absence maps structurally to `not_found`
  while invalid registry state maps to `conflict` without inspecting messages.
- Make `list_workspaces_strict()` apply the existing embedded-over-linked
  precedence once per slug, preventing duplicate list identities when both
  registrations exist.
- Reject non-canonical workspace slugs before filesystem resolution, closing
  the legacy path traversal ambiguity around `_Workspaces/{slug}` for the new
  command boundary.
- Cover exact reads, metadata, resolution, precedence, corrupt registries,
  invalid slugs and transport rejection in
  `tests/application/test_workspace_owners.py`.
- Align `src/brain-core/VERSION`, the README badge, and `BRAIN_INSTALL_REF`
  with v0.54.10. `BRAIN_CLI_VERSION` and `PROXY_VERSION` remain unchanged
  because their dispatch and protocols did not change.
