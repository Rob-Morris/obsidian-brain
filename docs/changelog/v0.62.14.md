# v0.62.14

**Summary:** Load semantic embeddings via onnxruntime instead of torch on Metal

**Type:** Brain Core patch

## Changed

- Replace the sentence-transformers and torch encoder with `LocalSentenceEncoder` in `_semantic/model.py`: `onnxruntime` pinned to `CPUExecutionProvider` plus `tokenizers`, mean pooling over the attention mask and L2 normalisation, reproducing the torch pipeline's vectors exactly so existing embeddings sidecars stay valid without a rebuild.
- Pin the semantic runtime to `onnxruntime`, `tokenizers`, `numpy` and `huggingface-hub` in `SEMANTIC_RUNTIME_PACKAGES`, the `Makefile` `install-semantic` target and the `semantic` extra in `pyproject.toml`; provisioning now downloads only `SNAPSHOT_FILES` instead of the whole model repository.
- Refuse snapshots without mean pooling and read `max_seq_length` from `sentence_bert_config.json` in `_load_local_encoder`, so a future model pin that needs a different pipeline fails at load time rather than producing different vectors.
- Lift the Intel macOS exclusion in `semantic_runtime_supported_platform` now that no torch wheel is required; the seam remains for future runtime pins.
- Cover the loader, pooling maths and an opt-in parity gate (`BRAIN_TEST_SEMANTIC_SNAPSHOT`) against recorded torch vectors in `tests/test_semantic_model.py` and `tests/fixtures/semantic/minilm_l6_v2_reference_vectors.json`; record the measured rationale in DD-070.
