# v0.54.3

**Implement foundational discovery and invocation-outcome owners**

- Add real application executors and authoritative catalogue entries for
  `command.list`, `command.describe`, and `invocation.read`; each typed request
  now resolves to exactly one owner through `CommandApplication.invoke`.
- Make `command.list` filter the bound catalogue by query, domain, authority,
  dependency tier, locality, effect class and supported projection, with
  deterministic bounded pagination and typed invalid-cursor errors.
- Make `command.describe` return the installed command identity/version or a
  structural `not_found` result without importing command executors dynamically.
- Make `invocation.read` return a conclusive typed receipt when present and
  explicit `still_unknown` state when no receipt proves an outcome; absence
  never becomes proof of no effects.
- Add strict foundational payload decoders that reject unknown fields, validate
  enum and scalar types, bind installed command versions and produce the same
  request objects used by direct Python.
- Tighten direct request and discovery-payload invariants so malformed domains,
  cursors, enum lookalikes, ordering and pagination cannot bypass adapter
  validation.
- Keep these owners internal to `_application`; the existing public MCP, CLI
  and direct-script grammar remains unchanged pending the coordinated cutover.
- Align `src/brain-core/VERSION`, the README badge, and `BRAIN_INSTALL_REF`
  with v0.54.3. `BRAIN_CLI_VERSION` and `PROXY_VERSION` remain unchanged
  because their public behaviour and protocols did not change.
