# v0.54.44

**Summary:** Establish mechanical application projection contracts

- Add one stdlib-only application projection owner for canonical command-to-MCP,
  CLI, direct-script and module names; resolution is catalogue-bound so aliases,
  stutter and ambiguous unowned names fail closed.
- Derive strict transport request schemas from sealed request dataclasses,
  including required/default fields, enums, nested structures, descriptions and
  rejection of additional properties without exposing command identity as input.
- Add one deterministic canonical result serializer for `ok`, known `partial`
  and no-effect/unknown `error` variants, including warnings, durable effects
  and outcome references.
- Check every installed application command for collision-free mechanical names
  and a recursively described strict request projection.
- Keep the new projection seam internal until the coordinated breaking MCP/CLI
  cutover; existing public adapters remain unchanged.
