# v0.54.43

**Summary:** Add typed Brain lifecycle launcher ownership

- Add `_launcher.lifecycle` with frozen `BrainInstallRequest`,
  `BrainUninstallRequest` and `BrainUpgradeRequest` owners over trusted
  distribution/selected-Brain context and bounded structural results.
- Require an explicit Brain ID for `brain.install`; add
  `vault_registry.preview_register_action()` so install dry-run validates the
  authoritative registry without creating its lock, directories or files.
- Make `brain.uninstall` preflight the fixed `.brain-core/`, `.brain/` and
  legacy `.venv/` deletion set, compose exact recorded MCP/registry cleanup,
  preserve user content/global state and retain recursive failure as unknown.
- Make `brain.upgrade` load `upgrade.py` from the trusted distribution, project
  closed sync policies and refresh the trusted CLI path through `FilePlan`.
  `file_transaction._write_bytes()` now preserves an existing target's mode.
- Keep public v1 installer, CLI and upgrade adapters unchanged until coordinated
  cutover; align Brain Core, README and `BRAIN_INSTALL_REF` at v0.54.43.
- Add `tests/application/test_launcher_lifecycle_owners.py` coverage for dry
  planning, partial install, selected-Brain cleanup, symlink refusal, recursive
  uncertainty, upgrade projection and executable CLI replacement.
