# v0.66.1

**Summary:** Prune vacated owner folders and repair empty artefact folders

**Type:** Backward-compatible Brain Core patch; CLI doctor repair mapping

Vault moves used to leave empty owner, status and month folders behind whenever
the last artefact left them, and nothing reported or removed the strays.
Pruning now lives in the shared move engine, and a new diagnostic and repair
scope clears whatever accumulated before this release.

## Changed

- `rename.move_and_update_links` gains an opt-in `prune_router` keyword: once every move has committed it removes the vacated source directories through `_common.prune_vacated_owner_folders`, rmdir-only, deepest-first within the vacated directory and then upward to the first non-empty directory or stop dir (type roots, `_Archive`, the vault root). Pruning never runs after a `PartialApplyError` and never touches directories outside artefact territory, so `_Assets/Attachments/` and `_Config/` are safe by construction.
- Every lifecycle move now prunes: `rename_artefact`, the `rename.py` CLI, ownership restructure, `convert_artefact`, `reparent_children`, `archive_artefact`, `unarchive_artefact` (emptying its `_Archive` mirror chain), temporal owner relocation in `_finish_artefact`, `_maybe_status_move`, `_repair_runtime.repair_ownership_locked`, `migrate_to_0_50_0` and router-backed `artefact.delete` via `rename.delete_and_clean_links(prune_router=...)`. The four hand-rolled post-move prune blocks in `edit.py` and the dead prune-failure `partial` branch in `_repair_runtime.py` are gone.
- The vestigial `router` parameter is removed from `move_and_update_links` and `preflight_move_set`; across `rename.py`, `router` now means validation or gating only and `prune_router` means prune, so `migrate_to_0_31_0`'s validation-only renames keep not pruning.
- New `empty_folders` compliance check (`check.check_empty_folders`, severity `info`, repairable) reports maximal vacated-empty directories — every entry an empty subdirectory or filesystem junk (`.DS_Store`, `Thumbs.db`) — under type roots and `_Archive`, via `_common.scan_empty_artefact_folders`. Type roots, `_Archive`, symlinks and `.`-prefixed directories are never reported. Vaults with existing strays will see new `info` findings; clear them with the repair below.
- New `empty_folders` repair scope: `repair.py empty_folders`, `artefact.repair` with `ArtefactRepairScope.EMPTY_FOLDERS`, and `_repair_runtime.repair_empty_folders` / `repair_empty_folders_locked`. The dry run lists every directory and junk file each finding would take; apply re-verifies each folder immediately before removal through `_common.remove_empty_artefact_folders`, skips any that changed since the scan, aborts before removal when a folder cannot be read, and reports per-folder `removed` / `skipped` / `failed` outcomes in its notes.
- `_REPAIR_COMMANDS` in `_application/vault/check.py` and `cli/_launcher/doctor.py` map `empty_folders` to `artefact.repair`; the application table's stale `mcp` entry now names the real launcher command `mcp.repair`. `tests/repair/test_repair_empty_folders.py::TestScopeWiring` asserts both tables cover every `REPAIR_SCOPES` key and resolve to real command ids.
- `_repair_runtime.repair_frontmatter` now takes the vault mutation lock like every other scope, delegating to the new `repair_frontmatter_locked` that `artefact.repair` calls under its own lock.
- `INCIDENTAL_ENTRIES` is defined once in `_common` and imported by `_bootstrap/agent_skills.py`; `_common.artefact_territory_roots` single-sources the root set that pruning and the scan both bound themselves to.
- `_maybe_status_move` requires the router and prunes the vacated `+Status/` folder through the move engine instead of its own `os.rmdir`.
- Docs: `docs/user/user-reference.md` recovery list and scope description, `docs/functional/mcp-tools.md` pruning and repair paragraph, `docs/user/workflows.md` repair command grammar, `repair.py` module docstring; `BRAIN_CLI_VERSION` 3.2.1 for the doctor mapping.
- Tests: `tests/test_owner_folder_pruning.py`, `tests/edit/test_edit_folder_pruning.py`, `tests/check/test_check_empty_folders.py`, `tests/repair/test_repair_empty_folders.py`, `tests/application/test_operator_mutation_owners.py`; the live-recomputed `command_interface_granular_mcp_projection_v1.json` fixture is regenerated for the grown `artefact.repair` scope schema.
