# v0.54.0

**BREAKING — Require explicit reparenting and recover degraded MCP schemas**

- Require callers to pass `brain_reparent.parent` explicitly, using JSON null
  only when they intend to clear ownership. Omitting the field no longer has
  the same destructive meaning as an explicit null.
- Keep the strict discriminated schemas for `brain_create`, `brain_edit`,
  `brain_define`, and `brain_action`, while adding one canonical request
  fragment to each concise tool summary for clients that collapse nested
  variants to opaque types.
- Reject legacy-looking `brain_create.body` and `content.kind` requests before
  mutation with actionable errors that name `content` and `source`; do not
  accept aliases or silently translate invalid requests.
- Describe every nested request property in `server.py`'s generated schema and
  make `tests/test_mcp_tool_contract.py` traverse reachable references, unions,
  and array items. The previous top-level-only traversal missed 61 fields.
- Remove `frontmatter` from `_BrainCreateTemplateRequest` and
  `CREATE_SPECS["template"]`, matching the full-document template contract while
  preserving an actionable correction for compatibility callers.
- Extend the MCP metadata contract in DD-060 and align
  `docs/functional/mcp-tools.md`, `docs/user/user-reference.md`, and
  `src/brain-core/guide.md` with the degraded-client recovery boundary.
- Align `src/brain-core/VERSION`, the README badge, and `BRAIN_INSTALL_REF` with
  v0.54.0. `BRAIN_CLI_VERSION` and `PROXY_VERSION` remain unchanged because
  neither helper's behaviour changed.

## Breaking change

Callers must now include `parent` in every `brain_reparent` request. Pass a
parent reference to reparent the artefact or JSON null to clear its current
parent. Requests that omit `parent` fail schema validation before mutation.

## Consequences

- Agents can recover common nested request shapes even when their MCP client
  hides the generated variants.
- Validation remains fail-closed and non-mutating while providing enough detail
  to correct the reported create mistake in one retry.
- Ownership cannot be cleared by an accidentally incomplete reparent request.
