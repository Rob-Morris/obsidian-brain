# v0.54.13

**Migrate typed search, classification, and resolution owners**

- Add granular `artefact.search`, `memory.search`, `plugin.search`,
  `skill.search`, `style.search` and `trigger.search` request, result, resolver
  and catalogue owners instead of carrying a resource discriminator.
- Add structural `content.classify` results for ranked and context-assembly
  strategies, plus a structural `content.resolve` duplicate decision.
- Preserve complete portable lexical, taxonomy-context and filename-resolution
  paths while declaring semantic retrieval as an optional provider only on the
  three commands that can actually use it.
- Require both trusted provider binding and a fresh available capability before
  an automatic or explicit semantic path can load selected-Brain sidecars.
- Return typed capability errors before semantic runtime loading when an
  explicit semantic request cannot be satisfied.
- Keep `_search` and `process.py` as the canonical retrieval, classification
  and duplicate-resolution algorithms; application owners validate and
  normalise their command contracts rather than cloning those semantics.
- Cover portable results, strict granular transport, exact catalogue metadata,
  semantic gating and provider-selected enhancement in
  `tests/application/test_optional_semantic_read_owners.py`.
- Align `src/brain-core/VERSION`, the README badge, and `BRAIN_INSTALL_REF`
  with v0.54.13. `BRAIN_CLI_VERSION` and `PROXY_VERSION` remain unchanged
  because their dispatch and protocols did not change.
