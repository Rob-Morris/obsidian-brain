# v0.50.1

**Harden recursive nested ownership safety and diagnostics**

- Make `brain_edit` handle documented partial-apply ownership failures like the other mutation surfaces: MCP now returns the repair context without an `Unexpected error` wrapper and marks router/index caches dirty after partial mutation.
- Stamp `modified` on the root artefact when an ownership edit writes frontmatter directly, while leaving descendant-only reference rewrites unstamped.
- Add defence-in-depth migration runner handling for any non-`ok`/`skipped` migration result so blocked future migrations halt without ledger recording.
- Prune empty vacated owner folders after successful v0.50.0 recursive migration moves, and report symlinked migration move endpoints as structured blockers instead of tracebacks.
- Tighten recursive ownership preflight consistency: pending ownership entries carry explicit living classification, descendant cycle diagnostics are deterministic, and move preflight avoids repeated source-identity rebuilds.
- Require explicit `recursive: true` when converting a living artefact with living descendants to a temporal type. Default convert now returns `HAS_DESCENDANTS`; recursive convert preserves the v0.50.0 cascade/deparent behaviour.
- Keep request-caused parent-cycle errors focused on the invalid request, while preserving vault-repair guidance for genuine cyclic or broken parent metadata.
- Align `cli/brain` install pin to `v0.50.1`; `BRAIN_CLI_VERSION` is unchanged because the shell dispatch surface did not change.
