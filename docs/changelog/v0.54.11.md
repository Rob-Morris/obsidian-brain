# v0.54.11

**Migrate bounded config, check, and type-status owners**

- Add typed `vault.read-config`, `vault.check` and `type.status` owners to
  complete the selected-Brain catalogue's portable read-only contract group.
- Make `VaultConfigPayload` expose only non-secret operational facts; operator
  records, authentication hashes and machine tool paths never cross the reader
  result boundary.
- Make `vault.read-config` fail with `conflict` for malformed nested config
  mappings or exclusion lists rather than leaking an internal exception.
- Give `VaultCheckRequest` typed severity/check/path filters and a bounded
  `VaultCheckFinding` result without timestamps or vault-root identity.
- Convert compliance repair metadata into canonical command identifiers such
  as `runtime.repair-router` and `retrieval.repair-lexical`; shell commands are
  not exposed as executable next actions.
- Flatten `type.status` into exact typed per-type/per-file states and return
  `not_found` when a requested artefact-library key is absent instead of the
  legacy empty-success result.
- Cover privacy, exact filtering, typed findings, invalid intent and transport
  rejection in `tests/application/test_portable_diagnostic_owners.py`.
- Align `src/brain-core/VERSION`, the README badge, and `BRAIN_INSTALL_REF`
  with v0.54.11. `BRAIN_CLI_VERSION` and `PROXY_VERSION` remain unchanged
  because their dispatch and protocols did not change.
