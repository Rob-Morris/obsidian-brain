# v0.59.1

**Summary:** Restore and enforce the naive-agent bootstrap contract

**Type:** Brain Core patch; shipped markdown, artefact-library definitions, and compliance surface

## Fixed

- Declare `key:` in the `## Frontmatter` example of the ten living artefact types that omitted it (`daily-notes`, `designs`, `documentation`, `ideas`, `notes`, `releases`, `tasks`, `wiki`, `writing`, `zettelkasten`), and add the matching `{{agent: ...}}` authoring hint to each template. `check.py`'s `check_living_key_fields` requires a valid key on every living artefact at severity `error`, so an agent authoring from shipped markdown alone previously produced non-compliant artefacts for ten of fourteen types.
- Route `.brain-core/md-bootstrap.md` to everything the degraded path needs: `session-core.md` for the artefact model, principles and standards index; `_Config/Taxonomy/{Living,Temporal}/` for type discovery; `standards/README.md` for the naming, key, wikilink and provenance contracts; plus `_Config/Skills/` and `guide.md`. Previously it reached only the router, preferences and gotchas, leaving the artefact model and every standard unreachable without MCP.
- Index `standards/keys.md` in both `session-core.md` and `standards/README.md`. The canonical key contract was absent from both, reachable only through `guide.md` via a memory file.
- Declare `parent` in the `living/release` frontmatter example and name it, its `Releases/{scope}/` placement and its relationship tag in the template hint. `schema.yaml` requires `parent`, but the example and template both omitted it, so releases could not be authored correctly from the naive surfaces. `living/daily-note` gains the same treatment for its required `date`.
- Declare `key` in the `required:` block of the ten living `schema.yaml` files that omitted it, so the machine-readable metadata matches the taxonomy examples and `check_living_key_fields`.
- Give the Notes and Wiki templates their schema-required `topic-tag`
  placeholder instead of an empty tag list.
- Prefix the `command.py` invocations in `md-bootstrap.md` with `python3`. The file is mode `644`, so the bare path form documented previously fails with permission denied; `docs/functional/scripts.md` already used the working form.
- Replace `md-bootstrap.md`'s instruction to follow a frontmatter example "exactly" with guidance to reproduce every declared field and substitute brace placeholders rather than copying them, which would emit unparseable YAML.
- Point `BRAIN_INSTALL_REF` in `cli/brain` and `cli/brain.cmd` at `v0.59.1`, with the matching references in `docs/functional/cli.md` and `docs/user/user-reference.md`. A VERSION bump without them makes fresh installs fetch the previous release and fails the CLI distribution contract.
- Make every `{{agent: ...}}` hint self-terminating. Tooling strips these tokens at create time, but a naive agent has none, so the hint now states that the line must be deleted once applied.
- Order the `md-bootstrap.md` tooling routes by capability: `brain` first, because its launcher enters the managed runtime and can therefore serve managed-tier commands such as `session.start`; `command.py` second, marked tier-limited.
- Align the two remaining `compile_router.py` run-instructions in `_Config/Memories/` with the canonical `brain runtime refresh-router` form already used across `standards/extending/`.

- Stop inferring frontmatter requiredness from the taxonomy example. `compile_router.py` treated every top-level key in a type's `## Frontmatter` example as required, so a documented-but-optional field was reported missing — a pre-ship `living/release` drew four spurious `frontmatter_required` warnings for `version`, `tag`, `commit` and `shipped` while that taxonomy's own prose states they "may stay blank". Requiredness is now declared: an optional `**Optional:**` line after the example names the fields that are not required, and fourteen shipped types declare one. The change is additive — a taxonomy without the line keeps the previous behaviour, so vault-authored custom types are unaffected. Fields used to select advanced naming rules remain required, and upgrade recompiles after syncing changed taxonomies so the installed router immediately reflects the declarations.
- Report a missing `key` once instead of twice. `check_frontmatter_required` now explicitly defers living `key` validation to `living_key_fields`, which covers every living artefact, including status folders, reports at error severity, and also validates key format. `parent` is deliberately not deferred: `check_parent_contract` only reports a missing parent when the folder implies an owner, so deferring would leave a release in `Releases/` root unreported.
- Make document-mutation failure reporting respect the file commit boundary. A `ValueError` or `FileNotFoundError` after the edit begins can no longer be projected as a safe no-effect failure; changed revisions become `command_outcome_unknown`. Failure of explicitly requested wikilink processing is now a typed partial result that reports the committed edit and a valid `artefact.read(reference=...)` follow-up.
- Complete the supported typed-Python construction surface. `brain_application.documents`, `brain_application.context` and the new `brain_application.values` façade export the request value types, context enums and receipt ports needed to construct every public request without importing private `_application` modules.
- Inventory durable receipts once per write instead of scanning and parsing the directory separately for expiry and trimming. Router freshness uses a bounded filesystem signature before collecting living counts and source hashes in one pass, and document mutations reuse one exact pre-write snapshot through revision validation and editing.
- Delete the unused 442-line `_application/_document_edit.py` implementation and replace the live mutation kernel's catch-all intent record with four typed operation variants. Dynamic adapter JSON, structured and concise renderings are now computed only when the selected transport asks for them.

## Added

- `check.py` gains `check_authoring_hint_tokens`, a warning-severity rule flagging `{{agent: ...}}` tokens left in a finished artefact body, so a leaked hint is caught however it arose — hand edit or agent. `AGENT_INSTRUCTION_RE` is promoted out of `_common/_templates.py` so the token format has one definition, and `CheckContext` now retains document text it already reads so the new rule adds no extra vault pass.
- `docs/standards/naive-agent-bootstrap.md` states the policy the layer is authored against: every schema-required field tooling injects must be visible without tooling; hints are self-terminating and live in the body; placeholders are prohibited in actual and template frontmatter while taxonomy examples may use them for substitution; scripts document behaviour while markdown documents contracts; naive routing stays contained to naive-specific files; and `standards/README.md` is the exhaustive index while `session-core.md` stays curated, since it is compiled into every MCP session payload.
- `DD-065` records the decision and extends `DD-038`;
  `tests/test_naive_bootstrap.py` enforces the standard.
- `**Optional:**` is documented as a taxonomy section in `standards/extending/adding-living-type.md` and `adding-temporal-type.md`, including the two constraints that bound it: naming a field the example does not show is a compile error, and a field the `## Naming` rules match on cannot be optional — which is why `Releases` and `Writing` keep `status` required despite its default.
- `src/scripts/check_repository_contracts.py` moves exact VERSION/changelog,
  decision-index, artefact-library metadata/count, manifest and documentation
  reachability facts out of subjective canary attestation. The pre-commit hook
  runs it against the staged snapshot with the repository Python environment.
  Manifest paths are portable, relative and vault-bounded; lifecycle equality,
  template placeholders and runtime-generated self-tags fail closed.
- `brain_application.values` is mechanically checked against the transitive
  construction types of every exported request, while a fresh-process test
  constructs trusted context and invokes both a read and a mutation using only
  supported `brain_application.*` imports.

## Verification

- `tests/test_naive_bootstrap.py` enforces the standard mechanically across the full public namespace — the five root docs plus the `standards/`, `artefact-library/`, `skills/` and `client-adapters/` trees. Every schema-required field must appear in its taxonomy example and be supplied or named by its template; every frontmatter example must parse as YAML and yield a contract-valid `key` once placeholders are substituted; every hint must be self-terminating; every cited `<noun>.<verb>` must exist in the catalogue; documented script invocations must name an interpreter; installed taxonomy folders must exist; and `standards/README.md` must be exhaustive.
- `tests/test_repository_contracts.py` covers the working-tree and staged
  predicates, including every former checklist equality and each review-found
  false-negative boundary.
- `check_authoring_hint_tokens` is exercised through `run_checks` against an installed vault clone, asserting the finding's file and severity rather than the rule in isolation.
- Document-mutation tests cover commit-then-`OSError`, `ValueError` and
  `FileNotFoundError`, wikilink partial results and single-snapshot reuse.
  Receipt and router-cache tests assert bounded scans, and adapter tests assert
  that unused transport renderings are not built eagerly.
- `tests/test_compile_router.py::TestFrontmatterOptionalFields` covers the declaration: absent means every documented key is required, declared fields are subtracted, naming an undocumented field raises, and a declaration outside the `## Frontmatter` section is ignored. `TestRequirednessOwnership` asserts a missing `key` yields exactly one finding and that no taxonomy declares a schema-required field optional.
- Each assertion was verified to fail when its invariant is broken, including the requiredness declaration in both directions — removing it from the installed taxonomy fails `TestTemplateVault`, and diverging it from the library source fails `test_no_drift`.
- Authoring a design and a task by following the corrected taxonomy examples produces zero key findings from `vault check`, where the same exercise against the previous examples produced `Living artefact missing a valid key field`.
