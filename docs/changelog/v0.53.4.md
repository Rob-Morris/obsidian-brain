# v0.53.4

**Add `brain_upload_attachment` for vault-safe asset uploads**

- Add `upload_attachment.py` as the canonical binary-safe operation for creating
  non-markdown files beneath a required living-artefact or standalone scope in
  `_Assets/Attachments/` from a caller-owned source file or base64 content
  without direct vault write access.
- Expose the same operation through `brain_upload_attachment` and
  `brain upload-attachment`; contributor and operator profiles may use it while
  the general `_Assets/` write guard remains unchanged.
- Make identical uploads retry-safe, reject different-content collisions, cap
  decoded content at 16 MiB, and return resolved destination metadata, vault
  path, Obsidian embed, byte count, SHA-256 digest, and `created` state.
- Move artefact-derived attachment scopes and rewrite embeds when a living key
  changes or converts to another living type. Preserve and report orphaned
  scopes on deletion or conversion to a temporal type.
- Leave existing flat attachments untouched; there is no automatic migration.
- Record the narrow security exception in
  `dd-059-attachment-upload-boundary.md` and align the MCP, script, CLI, user,
  security, architecture, and shipped guide references.
- Cover domain, path-containment, CLI, MCP, profile, and tool-schema behaviour in
  `tests/test_upload_attachment.py`, `tests/mcp_server/test_mcp_mutations.py`,
  `tests/mcp_server/test_mcp_session.py`, `tests/test_brain_cli.py`, and
  `tests/test_mcp_tool_contract.py`; extend `tests/test_windows_user_smoke.py`
  with an installed MCP attachment round trip.
- Align `src/brain-core/VERSION`, the README badge, and `BRAIN_INSTALL_REF` with
  v0.53.4. Bump `BRAIN_CLI_VERSION` to 1.2.0 for the new dispatch command;
  `PROXY_VERSION` remains unchanged because `proxy.py` behaviour did not change.

## Consequences

- Script-, CLI-, and MCP-only agents can add attachments without obtaining
  filesystem write permission to the vault.
- Attachment replacement remains deliberately unsupported: an existing
  filename with different bytes fails rather than overwriting content.
