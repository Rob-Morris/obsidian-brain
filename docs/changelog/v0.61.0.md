# v0.61.0

**Summary:** BREAKING — Add always-on content-free operational diagnostics

**Type:** Breaking Brain Core minor; diagnostics and observability contract

## Changed

- Add bounded, content-free NDJSON operational logs for the MCP proxy, server,
  command application and CLI launcher under `.brain/local/diagnostics/`.
- Persist correlation-aware failure records for read-only and mutating commands
  without admitting request bodies, vault content or caller-selected paths.
- Make multi-process append, rotation, export and clearing use a bounded
  stdlib-only file layer with explicit locking, retention and drop reporting.
- Refuse symlinked or non-regular diagnostics locks and logs before append,
  truncation or export; use unique exclusive proxy writability probes so
  concurrent starts cannot delete each other's state.
- Enforce closed per-event operational schemas and project unrecognised
  JSON-RPC methods to `other`, preventing caller-shaped fields or values from
  becoming a content channel.
- Keep opt-in raw protocol bodies isolated in `debug-bodies.log`; operational
  logs remain content-free regardless of debug configuration.
- Advance the MCP proxy to 0.8.0 and the CLI distribution to 3.0.1 so upgrades
  can distinguish the changed shipped helpers from their v0.60 counterparts.

### Release preparation

**Make release preparation explicit and keep commit validation read-only**

- Add `src/scripts/release.py status`, `prepare` and `export` owners for
  comparing Git release views, applying explicitly selected release mechanics
  and materialising an exact committed source tree.
- Make `.githooks/pre-commit` validate the index without rewriting or staging
  `README.md`; add `make precommit-check` as the same deterministic preflight
  before a commit attempt.
- Make `cli._distribution.source_versions` the Python owner for the shipped
  Core/CLI pair, removing duplicated `3.0.1` literals from launcher and upgrade
  execution paths.
- Share one pure `cli._version_contract` parser across distribution install,
  repository validation and `src/scripts/release.py` status instead of
  maintaining three release grammars.
- Make `src/scripts/release.py` attempt every transaction restoration and
  report incomplete rollback plus retained recovery paths without masking the
  initiating write failure.
- Extend `src/scripts/check_repository_contracts.py` to keep Unix and Windows
  bootloader versions, install refs and canonical CLI documentation in parity.
- Restore semantic release intent to `.canaries/pre-commit.md`, while leaving
  version equality and other deterministic facts to tooling.

## Removed

- Retire the prose `.brain/local/mcp-proxy.log` writer and `BRAIN_LOG_LEVEL`.
  Human-readable proxy warnings remain on stderr; `BRAIN_LOG_BODIES` now writes
  only to the separate bounded debug-body stream.

## Verification

- Operational-log tests cover schemas, identifier bounds, permissions,
  rotation, retention, concurrent append, lock contention, dropped-record
  accounting and bounded shutdown.
- Proxy, server, application and launcher tests cover lifecycle and failure
  wiring without changing command outcomes when diagnostics are unavailable.
- Import-boundary tests keep the logging implementation stdlib-only and usable
  from bootstrap and one-shot execution planes.
- `tests/test_release_tooling.py`, `tests/test_repository_contracts.py` and
  `tests/application/test_cli_distribution.py` cover dry-run preparation,
  immutable commit export, exact-index hook behaviour and component-version
  drift.
- `tests/test_operational_log.py` reproduces symlink endpoint attacks, closed
  event-schema rejection and bounded queue draining;
  `tests/test_proxy_degraded_mode.py` races concurrent startup probes;
  `tests/test_mcp_proxy.py` forwards malformed method types without crashing;
  and `tests/mcp_server/test_granular_command_adapter.py` plus
  `tests/application/test_local_cli_execution.py` exercise real MCP tool-span
  and launcher failure/correlation boundaries.
