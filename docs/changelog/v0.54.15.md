# v0.54.15

**Migrate typed memory, skill, and style creation owners**

- Add granular `memory.create`, `skill.create` and `style.create` request,
  result, resolver and catalogue owners under contributor authority.
- Introduce shared immutable inline/staged content variants using the canonical
  `source` discriminator; caller-owned body-file paths cannot enter the
  application request.
- Represent optional resource frontmatter as deterministic typed fields with
  scalar or flat scalar-list values instead of a mutable open dictionary.
- Preserve naming, paths, full-document validation, exclusive creation and
  stale-router safety through the existing `create.py` semantic owner.
- Consume staged content only after creation commits; retain its handle on
  duplicate, stale-router or validation failure, and surface cleanup problems
  as typed follow-up warnings.
- Refuse dry-run rather than returning a fictitious created resource, and map
  unexpected post-commit failure to queryable `command_outcome_unknown`.
- Cover all three paths, frontmatter, staged success/failure, dry-run, strict
  transport, catalogue metadata and injected uncertainty in the disposable
  command vault.
- Align `src/brain-core/VERSION`, the README badge, and `BRAIN_INSTALL_REF`
  with v0.54.15. `BRAIN_CLI_VERSION` and `PROXY_VERSION` remain unchanged
  because their dispatch and protocols did not change.
