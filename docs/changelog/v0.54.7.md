# v0.54.7

**Migrate exact memory and trigger collection owners**

- Add distinct typed `memory.read/list` and `trigger.read/list` owners with
  exact bounded payloads, strict transport decoding and separate catalogue
  identities.
- Make new `memory.read` resolve an exact memory name; trigger-phrase discovery
  belongs to the separate `memory.search` command at cutover rather than
  overloading a read with ambiguous search results.
- Use the router's unique exact trigger `condition` as the canonical selector
  for `trigger.read`, with category constrained to `before | after | ongoing`.
- Add adapter-free memory/trigger collection views that expose bounded
  metadata and case-insensitive query filtering over real trigger fields.
- Correct existing trigger reads and filtered lists, which previously assumed
  compiled triggers had a `name` field and therefore could not match normal
  router records.
- Add installed command-vault and legacy regressions for exact memory reads,
  trigger conditions, bounded filters, not-found behaviour and strict request
  shapes.
- Keep the wider public MCP, CLI and direct-script grammar unchanged until the
  coordinated breaking cutover.
- Align `src/brain-core/VERSION`, the README badge, and `BRAIN_INSTALL_REF`
  with v0.54.7. `BRAIN_CLI_VERSION` and `PROXY_VERSION` remain unchanged
  because their dispatch and protocols did not change.
