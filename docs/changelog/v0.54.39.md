# v0.54.39

**Add fail-closed orphan-runtime pruning launcher ownership**

- Add the typed `_launcher.machine` owner for `machine.prune-runtimes`, with
  bounded no-op, planned and removed target results.
- Carry the current Brain only as trusted launcher context so unregistered
  current-vault runtimes participate in orphan classification without becoming
  caller-controlled request data.
- Reuse the existing machine topology and pruning owner through a read-only
  derived-registry comparison; canonical pruning no longer rewrites
  `brains.json` as a hidden preliminary effect.
- Require successful live-process detection before removal, return a known
  no-effect conflict when discovery cannot prove safety, and report each
  removed runtime directory as a committed effect.
- Treat any filesystem deletion failure as non-retryable outcome uncertainty
  because a recursive removal may already have changed part of the target.
- Align Brain Core, the README badge and `BRAIN_INSTALL_REF` at v0.54.39;
  CLI and proxy protocol versions remain unchanged.
