# Brain Core 0.56.0

**Consolidate target-only commands and restore runtime warm-up contracts.**

- Replace 25 target-only named-resource and rendering leaves with the strict
  `resource.create`, `resource.list`, `resource.read`, `resource.search` and
  `shaping.render` commands. Resource-specific request and result variants
  remain closed and discriminated; template creation still cannot accept
  separate frontmatter.
- Retain `artefact.reparent`, `artefact.set-key`,
  `artefact.set-naming-field` and `artefact.set-status` as directly searchable
  commands because they express distinct user intents.
- Keep `artefact.migrate-naming`, `retrieval.enable` and
  `workspace.repair-registry` available through CLI, direct script and typed
  Python while explicitly excluding them from agent-facing MCP.
- Add bootstrap-safe `runtime.status` and `runtime.warmup` over one exact
  `brain.runtime-status/1` snapshot. Cold `session.start` now starts or joins
  warm-up, returns promptly with polling guidance and builds the managed
  session only after readiness.
- Reconcile the authoritative surface to 68 application commands and 57 MCP
  tools. The supported Claude and Codex projections measure 7,778 and 7,982
  deterministic tokens respectively, below the release ceiling.
- Run `migrate_to_0_56_0.migrate()` once during upgrade so the exact shipped
  v0.55 profile set adopts the new built-ins while custom profiles receive
  only command-for-command replacements and never gain new authority.
- Update the shipped `presentations`, `printables` and `shaping:assess` skills,
  plus template-vault memory guidance, to call the consolidated
  `resource.read`, `resource.list` and `shaping.render` contracts.
