# v0.71.0

**Summary:** Make maintenance explicit and upgrades recoverable

**Type:** Breaking Brain Core minor; explicit registration and recoverable upgrades

## Changed

- Replace derived machine registration and one-ended workspace writers with explicit canonical owners; migrate retired workspace grants without widening custom profiles.
- Drive maintenance from current findings and subject or evidence identities; make Doctor read-only and scope diagnostics to the selected Brain.
- Use role-named managed interpreters and full process command lines for runtime diagnosis; clarify host tool rediscovery after Core refresh.
- Guard same-version force upgrades against content drift and migration replay, and recover interrupted upgrades through a persistent rollback journal.
- Stored and customised profiles retain their existing permission ceilings; maintenance access must be added explicitly where needed.
- If the first upgrade is interrupted before CLI cutover, resume from the new source installer or upgrade.py --source; the old installed launcher may still contain the old upgrader. Rollback snapshots and recovery copies can retain authored content and configuration outside the vault.
- Retain source VERSION file permissions at the final commit so upgraded copies remain compatible with exact-source Brain Lab rehydration; journal writes remain private.
