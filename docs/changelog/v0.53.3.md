# v0.53.3

**Surface local workspace binding guidance through `brain_session`**

- Add `workspace_configuration` to the canonical `session.py` model and
  markdown renderer so agents see the local
  `brain configure workspace binding` command template, current binding status, and
  the no-artefact effect even without active workspace context.
- Keep `brain configure workspace binding` as the only execution surface for
  workspace binding. The session guidance explicitly labels it as local CLI
  work, explains local Brain selection, and never substitutes a server
  filesystem path into the client-local command.
- Extend `tests/test_session.py` and
  `tests/mcp_server/test_mcp_session.py` across capability discovery, binding
  state, and MCP/generated-markdown parity.
- Align the MCP, CLI, setup, architecture, and shipped guide documentation
  around the local-client versus remote-Brain boundary.
- Align `src/brain-core/VERSION`, the README badge, and `BRAIN_INSTALL_REF`
  with v0.53.3; `BRAIN_CLI_VERSION` remains unchanged because CLI dispatch
  behaviour did not change.

## Consequences

- MCP-connected agents discover the local command without scanning the
  filesystem or mistaking a Brain-host operation for a client-local one.
- Humans and agents use the same CLI implementation for workspace binding.
- Session bootstrap grows one concise capability record, available even when
  no workspace is currently known.
- MCP retains its existing host-side boundary; it does not claim authority
  over the connecting agent's local filesystem, and says so explicitly in the
  session payload.
