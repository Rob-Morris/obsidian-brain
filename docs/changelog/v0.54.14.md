# v0.54.14

**Migrate typed staging and attachment mutation owners**

- Add granular `stage.create`, `stage.discard` and `attachment.upload` request,
  result, resolver and catalogue owners under contributor authority.
- Give all three commands selected-Brain mutation effects and receipt-required
  retry contracts, with compact committed-effect subjects for created or
  removed resources.
- Preserve staged-body quotas, expiry, opaque handles and idempotent discard
  through the existing `_staging` semantic owner.
- Keep attachment validation, destination resolution, path containment,
  collision handling, hashing and idempotency in `upload_attachment.py`.
- Accept attachment bytes only as bounded inline base64 at the canonical
  command boundary; caller-owned file paths remain adapter-local inputs.
- Return dry-run attachment plans without writes, refuse unusable dry-run stage
  creation, and treat dry-run discard as a no-effect observation.
- Map validated no-effect failures structurally while allowing unexpected I/O
  after mutation entry to become non-retryable `command_outcome_unknown`.
- Cover authority-before-effects, idempotency, dry-run, strict transport and
  post-commit failure behavior in dedicated application owner tests.
- Align `src/brain-core/VERSION`, the README badge, and `BRAIN_INSTALL_REF`
  with v0.54.14. `BRAIN_CLI_VERSION` and `PROXY_VERSION` remain unchanged
  because their dispatch and protocols did not change.
