# Vault Tooling Maturity - Pass 2 (v0.31.0-v0.51.0)

Shipped: 2026-07-08

## Overview

Vault Tooling Maturity - Pass 2 is the long arc from Brain's first canonical
ownership model to a safer, more observable local-vault runtime. Across
`v0.31.0` through `v0.51.0`, Brain gained stable living artefact keys,
parent-backed ownership, a stricter `brain_edit` contract, explicit repair and
upgrade surfaces, operational semantic retrieval, a managed runtime and `brain`
CLI, workspace-aware MCP configuration, native Windows install support,
recursive nested ownership, owner-scoped temporal filing, stale derived-state
gates, partial-apply diagnostics, and table-aware wikilink mutation.

The common theme is that Brain's tools now treat the vault as structured local
state rather than loose markdown files. Mutations resolve through compiled
router state, ownership and naming are deterministic, repair guidance is
actionable, and MCP/script paths share the same fail-loud boundaries instead of
silently guessing.

Representative small/medium/large vault performance validation was explicitly
deferred to a follow-on performance and scale-validation release; it is not part
of this release gate.

## Breaking changes

- `v0.32.0` shipped the breaking `brain_edit` structural contract. Body and
  section edits now use explicit `target`, `scope`, selector, and occurrence
  parameters; older target spellings such as `:entire_body`,
  `:body_preamble`, and `:section:## Heading` are rejected with migration
  guidance.
- `v0.44.0` moved workspace binding out of implicit bootstrap state and into
  `setup` / `configure`. Project-aware MCP now resolves the active Brain through
  explicit workspace binding rather than assuming a launch directory is enough.
- `v0.49.0` retired `init.py` and the `brain init` dispatch noun. Current MCP
  transport management lives under `configure`.
- `v0.50.0` changed recursive ownership semantics. Descendant-bearing delete,
  archive, convert, reparent, and ownership-edit flows now validate the whole
  affected ownership tree and require explicit recursive intent where data would
  be removed or cascaded.

## Highlights

- **Canonical ownership became the vault's structural backbone.** `v0.31.0`
  introduced stable living `key:` values, canonical `parent: {type}/{key}`
  references, a compiled `artefact_index`, owner-derived folders, parent drift
  checks, and a three-phase migration to backfill keys and parents. Follow-up
  work refined distinctive key generation, scope terminology, workspace
  metadata, release artefact ownership, and completed-workspace handling.
- **Artefact mutation moved onto an explicit, verifiable contract.** `v0.32.0`
  replaced implicit body-edit targets with the shared structural
  `target + selector + scope` model, then later releases collapsed duplicate
  edit entry points, tightened heading intro boundaries, kept config-resource
  edits out of artefact indexes, and made `brain_move` the first-class tool for
  content movement.
- **Agent-facing standards and review tools became part of the product.**
  `v0.32.10` added the `code-review` core skill family, `v0.35.3` shipped
  software-design review/principle skills, `v0.35.6` codified how to extend
  living and temporal artefact types, and `v0.43.0` unified closure statuses
  around `deprecated` / `parked` so agents and humans use the same lifecycle
  vocabulary.
- **Install, upgrade, repair, and runtime ownership were made explicit.**
  `upgrade.py` became the upgrade owner, `repair.py` became the current-vault
  recovery surface, dry-runs gained migration/sync previews, migration ledgers
  and rollback paths were hardened, duplicate frontmatter became detectable and
  repairable, and strict migration statuses now halt without recording ledger
  success unless the result is `ok` or `skipped`.
- **MCP startup and machine runtime stopped depending on client patience.**
  `brain_init` split cheap bootstrap state from background warmup, the MCP proxy
  gained explicit restart/backoff behaviour, readiness guidance moved into a
  shared server-readiness layer, the managed Python runtime moved under
  `~/.brain/venvs`, and the `brain` CLI became the public launcher for setup,
  configure, repair, doctor, and script dispatch.
- **Brain resolution, workspace binding, and transport setup converged.**
  The active Brain is now resolved through a unified ladder with stale-state
  termination, workspace binding is configured explicitly, vault-self MCP mode
  is available when needed, legacy configs self-heal on proxy startup, and MCP
  transport management lives under `configure` rather than retired `init.py`.
- **Semantic and lexical retrieval became operational, repairable subsystems.**
  `v0.36.x` made semantic retrieval work across MCP, process, and search with
  benchmark tooling, hybrid tuning, explicit model provisioning, and drift
  detection. `v0.40.x` consolidated retrieval under `_search`, split lexical
  and semantic responsibilities, made unreadable sources fail explicitly, and
  connected repair/check/doctor diagnostics to the same derived-cache state.
- **Windows and cross-platform support moved from best-effort to deliberate.**
  Native Windows install and MCP smoke support landed in `v0.48.6`, with
  platform-aware paths, locks, shell quoting, managed-runtime lookup, launcher
  scripts, graceful Obsidian CLI degradation, and Windows-safe transport
  behaviour.
- **Wikilink and markdown mutation became safer at write time.** Mutation-time
  `fix_links` now verifies against a filesystem index when correctness requires
  it, stale derived-cache state reports repair guidance through `check.py` and
  Doctor, and `v0.51.0` makes rename, fix-links, edit, and check table-aware so
  unsafe aliases inside markdown table rows do not corrupt cell boundaries.
- **Recursive nested ownership completed the ownership model.** `v0.50.0`
  added `migrations/migrate_to_0_50_0.py`, recursive owner-folder migration,
  parent-chain and stale-index fail-loud checks, shared move-set preflight,
  cycle/collision/symlink/destination validation, recursive delete/archive,
  reparent, and rollback-preserved migration diagnostics. `v0.50.1` added MCP
  partial-apply handling, dirty-state marking, vacated-folder pruning, explicit
  `recursive: true` for living-to-temporal conversion with descendants, and
  clearer request-cycle wording. `v0.50.2` preserved strict migration handling
  while accepting the legacy no-op repair as top-level `skipped`.
- **Parented temporal artefacts now follow their owner chain.** `v0.51.0`
  closes the final Pass 2 gap: create, convert, and edit relocation paths file
  parented temporal artefacts under the living owner chain before the `yyyy-mm`
  folder, including temporal child rehomes after living owner key or parent
  changes. Existing parented temporal files are not auto-refiled by this
  release.
- **Direct scripts and MCP now share the same mutation safety story.**
  `create.py`, `edit.py`, `rename.py`, and `fix_links.py` refuse stale or
  unreadable compiled router state before mutating or scanning for fixes;
  documented partial applies surface durable repair context instead of generic
  tracebacks; script, MCP, user, security, and shipped-guide docs describe the
  same boundaries.

## Upgrade notes

- Run the normal upgrade flow. If a direct mutation script reports stale
  compiled router state, run `compile_router.py` or `repair.py router` before
  retrying the mutation.
- Existing callers using the pre-`v0.32.0` `brain_edit` target spellings must
  move to the explicit `target` / `scope` / selector contract documented in
  `docs/functional/mcp-tools.md`.
- Install or automation flows that still call `init.py` or `brain init` must use
  `configure` for MCP transport setup and removal.
- Workspace-aware MCP installs should confirm their workspace binding through
  `setup` / `configure`; launch-directory inference is no longer the ownership
  boundary.
- Existing parented temporal artefacts are not automatically refiled by this
  release. New create/convert/edit relocation flows use owner-scoped temporal
  folders going forward.
- `check.py` may now warn on aliased wikilinks inside markdown tables as
  `table_wikilink_alias`. Remove the alias or rewrite the cell with a plain
  wikilink.
