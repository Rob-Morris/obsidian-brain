# v0.76.2

**Summary:** Recover Doctor findings and bound CI fixture storage

**Type:** Brain Core and CLI patch; diagnostics and contributor verification

## Changed

- `brain doctor` recovers complete `vault.check` findings across bounded pages and nested details within the original private result session. Recovery validates identity and coverage, shares the existing deadline, and reports unavailable diagnoses instead of crashing or reporting false health. Offline CLI version probes avoid loading live services.
- `brain session run` jobs retain an actionable invalid-request diagnostic when a child selects a conflicting result session. The exact released-Core refusal is recognised without echoing credentials or arbitrary stderr, and explains inheriting the job session or supplying the same private file to outer job and child. Core credential and consent checks are unchanged.
- `docs/CONTRIBUTING.md` scopes development verification to relevant serial tests for bounded changes while retaining full candidate and hosted certification. `copy_install_source` omits redundant engine and bytecode copies, pytest reports slow phases, and `promotion.py` checks candidate-owned Lab compatibility before expensive verification.
- `pytest_test_resources` releases successful test scratch only after complete teardown, preserves failed/interrupted evidence, and stops after independently confirming actual filesystem exhaustion. Command-vault clones omit generated bytecode. Linux CI publishes bounded failure snapshots and filesystem diagnostics instead of requiring huge console-log downloads.
