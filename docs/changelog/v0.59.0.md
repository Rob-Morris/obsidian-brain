# v0.59.0

**Summary:** BREAKING — Split document mutations and require exact revisions

**Type:** Brain Core minor; breaking command-contract change

## Changed

- Replace the broad document-mutation union with four intent-specific commands: `document.write` for complete-body writes, `document.patch` for literal substitution, `document.edit` for typed Markdown structures, and `document.update-frontmatter` for metadata.
- Require every document mutation to supply the exact revision returned by `artefact.read` or editable `resource.read`; return the new revision after a successful effect.
- Calculate read revisions from the exact persisted bytes while retaining normalized newline text for callers, so CRLF documents support the same read–mutate contract.
- Add a stable `brain_application` Python facade and separate supported-API docstring coverage from generated command-contract documentation.
- Add a v0.59.0 migration that projects exact shipped profiles and explicit legacy document-edit grants onto the replacement commands without widening unrelated custom profiles.
- Align `cli/brain` and `cli/brain.cmd` to install Brain Core v0.59.0 while retaining `BRAIN_CLI_VERSION=2.1.0` because CLI dispatch is unchanged.

## Verification

- Application tests cover every write, patch, structural edit and frontmatter-update intent across artefacts and named editable resources, including stale revisions, CRLF content and uncertain outcomes.
- Profile and upgrade tests cover the v0.58.0-to-v0.59.0 authority migration for exact built-ins and explicit custom grants.
- Cross-adapter projections and real-client captures enforce the new request and result contracts.
