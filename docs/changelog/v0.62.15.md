# v0.62.15

**Summary:** Run semantic rebuilds in a fresh interpreter, not the MCP server

**Type:** Brain Core patch

## Changed

- Add `_lifecycle/fresh_interpreter.py`: `run_lifecycle_in_fresh_interpreter` runs one `_lifecycle.<module>:<function>` owner in a child interpreter over a JSON stdin/stdout contract, re-raising owner failures as `FreshInterpreterError` and keeping the reply channel clean of owner output.
- Route `retrieval.enable`, `retrieval.repair-semantic` and `retrieval.rebuild-semantic` through that runner in `_application/_semantic_maintenance.py`, so a full-corpus embedding encode no longer leaves several hundred megabytes resident in a long-lived MCP server; the vault mutation lock is still taken by the calling process.
- Move the rebuild owner to `_lifecycle/retrieval_assets.py::rebuild_semantic_assets` so it is addressable by the runner alongside `enable_semantic` and `repair_semantic`.
- Cover the runner end to end with a real child process, target validation, owner-exception mapping and missing-reply reporting in `tests/test_fresh_interpreter.py`; `tests/application/test_semantic_maintenance_owners.py` now stubs the runner seam instead of the owners.
